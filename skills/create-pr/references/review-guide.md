# How to review

The `How to review` section MUST tell a reviewer who doesn't know the code
where to start, in what order to read, and what each part leans on. The agent
MUST build it from the diff and the imports, and MUST NOT guess.

## What goes in it

- **Entry point** the first line MUST name the one place the change starts:
  the screen, the command, the route, the job or the function a person or a
  trigger reaches first, with its file. One sentence on what happens there.
- **Reading order** a numbered list MUST follow, a file or folder per step,
  in the order the reviewer SHOULD read: the entry point first, then what it
  calls, then shared code, then tests. Each step MUST say what to check there
  in a few plain words: "the size check", "the new error text".
- **Map** a `flowchart TD` MUST show the changed files and the ones they call:
  an arrow goes from the caller to the code it calls. It MUST follow the
  colours of [diagrams.md](diagrams.md), as one After block: the map shows how
  the code reads now, so it needs no Before pair.
- **Skim** a last line MUST name the parts a reviewer MAY skim: generated
  files, lockfiles, moved code, renames, snapshots. It SHOULD point at
  `Generated by commands` when that section exists.
- **Risk** the step with the riskiest logic SHOULD get a bold `Look here`,
  with the reason in a few words: "the only place that deletes rows".

## How to write it

- **Plain words** each step MUST read like a note to a new teammate on day
  one. A name from the code MUST get a few words on what it does.
- **Nodes** a node SHOULD be the file name plus what it does there, in
  quotes: `A["upload.ts: checks the size"]`. Ten nodes at most.
- **Small PR** a change of one or two files MAY drop the list and the map,
  and keep one line: the file to open and what to check there.
- **Tests** the order SHOULD place each test right after the code it tests,
  or last when they cover several steps.
- **Find the links** the agent SHOULD read the imports the diff adds or
  changes: `git diff "$base"...HEAD | grep -E '^\+.*(import|require|use) '`.

## Example

The section SHOULD read like this:

````markdown
## How to review

Start at `src/ui/UploadButton.tsx`: the person picks a photo there.

1. `src/ui/UploadButton.tsx`: the button stays off while a file uploads.
2. `src/api/upload.ts`: **Look here**, the new 25 MB limit, the only check on size.
3. `src/ui/SizeError.tsx`: the error shows the limit and the file size.
4. `src/api/upload.test.ts`: the cases at 25 MB and just above it.

```mermaid
flowchart TD
  A["UploadButton.tsx: picks the photo"]:::changed --> B["upload.ts: checks the size"]:::changed
  B -->|too big| C["SizeError.tsx: shows the error"]:::new
  B --> D["formatBytes: prints 25 MB"]:::same
  classDef ...
```

Skim: `pnpm-lock.yaml`, written by `pnpm add`.
````

The `classDef ...` line above stands for the four lines of
[diagrams.md](diagrams.md), and the agent MUST write them out.
